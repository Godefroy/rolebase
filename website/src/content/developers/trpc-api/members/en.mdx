Procedures of the `member` router. Creating a member row and editing its name, picture or work data is plain GraphQL on the [`member`](/en/developers/graphql-api/member) entity; these procedures handle the invitation flow, the access role and the seat count of the subscription, which all need server-side logic.

An access role is `Readonly`, `Member`, `Admin` or `Owner`, and see [Permissions](/en/developers/permissions) for what each one grants.

## Mutation `member.inviteMember`

Sends an invitation email to an existing member, for an Admin or Owner. Inviting with the `Owner` role, or resending an `Owner` invitation, requires Owner. Calling it again on an already invited member resends the email with a fresh token.

| Input      | Type     | Description                                           |
| ---------- | -------- | ----------------------------------------------------- |
| `memberId` | `uuid`   | Member to invite, not yet linked to a user. Required. |
| `email`    | `String` | Address the invitation is sent to. Required.          |
| `role`     | `String` | Access role granted on acceptance. Required.          |

The member row keeps the invitation email and date, from which the invitation token is derived. A member already linked to a user answers `CONFLICT`, and the call is refused when the subscription has no seat left for one more member. It returns nothing.

```typescript
await trpc.member.inviteMember.mutate({
  memberId: 'YOUR_MEMBER_ID',
  email: 'someone@example.com',
  role: 'Member',
})
```

## Query `member.getMemberInvitationInfo`

Reads what an invitation link needs to show before the recipient signs in, so this procedure takes no authentication.

| Input      | Type     | Description                                     |
| ---------- | -------- | ----------------------------------------------- |
| `memberId` | `uuid`   | Invited member. Required.                       |
| `token`    | `String` | Token carried by the invitation link. Required. |

It returns `{ orgName, email }`. A member with no pending invitation answers `NOT_FOUND`, and a token that does not match answers `UNAUTHORIZED`.

## Query `member.getPendingInvitations`

Lists the invitations waiting for the signed-in user, matched on their email address. It takes no input and is used to offer joining an organization to a user who has none.

It returns an array of `{ memberId, token, orgId, orgName }`, ready to pass to `member.acceptMemberInvitation`. An unverified email address returns an empty array, since sign-up alone proves nothing about who owns the address.

## Query `member.getColleagueOrgs`

Lists the active organizations where accounts with the same company email domain as the signed-in user are members, and the user is not. It takes no input and lets the onboarding offer to request access to the team's organization instead of creating a new one.

It returns an array of at most 3 `{ orgId, orgName, requestStatus }`, the organizations with the most members first. `requestStatus` is the status of the user's last access request to the organization (`Pending`, `Accepted` or `Refused`), or `null`. An unverified email address or a shared domain returns an empty array: free mailbox, alias or disposable inbox (Gmail, Firefox Relay, Yopmail and the other domains of the disposable-email-domains list...), student subdomain, French education academy (`ac-*.fr`) or `.edu` domain.

## Mutation `member.requestOrgAccess`

Asks to join one of the organizations returned by `member.getColleagueOrgs`. Its Admins and Owners are notified by email.

| Input   | Type   | Description                     |
| ------- | ------ | ------------------------------- |
| `orgId` | `uuid` | Organization to join. Required. |

An organization that is not a colleagues' organization of the user answers `FORBIDDEN`, and a request already pending answers `CONFLICT`. It returns nothing.

## Query `member.getOrgAccessRequests`

Lists the pending access requests of an organization, for its Admins and Owners.

| Input   | Type   | Description                    |
| ------- | ------ | ------------------------------ |
| `orgId` | `uuid` | Target organization. Required. |

It returns an array of `{ id, createdAt, name, email, avatarUrl }`, the oldest first.

## Mutation `member.decideOrgAccessRequest`

Accepts or refuses an access request, for an Admin or Owner of the organization. The requester is told by email either way.

| Input       | Type      | Description                                    |
| ----------- | --------- | ---------------------------------------------- |
| `requestId` | `uuid`    | Access request. Required.                      |
| `accept`    | `Boolean` | `true` to accept, `false` to refuse. Required. |

Accepting adds the requester as a member right away, with the `Member` access role, and updates the Stripe subscription seat count when the organization has an active subscription. A subscription without a free seat blocks the call. A request already decided answers `NOT_FOUND`, or `CONFLICT` when another admin decided it at the same time. It returns nothing.

## Mutation `member.acceptMemberInvitation`

Links the invited member to the signed-in user and applies the invited access role.

| Input      | Type     | Description                                     |
| ---------- | -------- | ----------------------------------------------- |
| `memberId` | `uuid`   | Invited member. Required.                       |
| `token`    | `String` | Token carried by the invitation link. Required. |

The invitation is consumed, and the Stripe subscription seat count is updated when the organization has an active subscription. When this is the first organization of the user, `invitation` is recorded as their onboarding source. A user who already belongs to the organization answers `CONFLICT`, and a subscription without a free seat blocks the call. It returns nothing.

## Mutation `member.updateMemberRole`

Changes or removes the access role of a member. An Admin can act on any member, while changing the role of an Owner or granting the `Owner` role requires Owner, and the last active Owner cannot be demoted. Members cannot change their own role, which answers `FORBIDDEN`.

| Input      | Type     | Description                                                                                                  |
| ---------- | -------- | ------------------------------------------------------------------------------------------------------------ |
| `memberId` | `uuid`   | Target member. Required.                                                                                     |
| `role`     | `String` | New access role, or an empty value to revoke the access while keeping the member in the org chart. Required. |

A member who was never invited answers `NOT_FOUND`. It returns nothing.

## Mutation `member.archiveMember`

Archives a member, unlinking it from its user account and clearing its access role and invitation. An Admin can archive any member, archiving an Owner requires Owner, and the last active Owner is protected. Members cannot archive themselves, which answers `FORBIDDEN`: they use `member.leaveOrg`.

It takes `{ memberId }`, updates the subscription seat count when the member was linked to a user, and returns nothing.

## Mutation `member.leaveOrg`

The current user leaves an organization: their member is archived like with `member.archiveMember`, without needing an Admin role. It takes `{ orgId }`, updates the subscription seat count and returns nothing. The last active Owner cannot leave, which answers `BAD_REQUEST`.

## Mutation `member.restoreMember`

Restores an archived member, for an Admin or Owner. It takes `{ memberId }` and returns nothing. The member comes back without an access role, so invite it again to give it access.
