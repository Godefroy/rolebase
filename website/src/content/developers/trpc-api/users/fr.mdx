Procédures du routeur `user`. Le compte lui-même (nom, langue, métadonnées) se lit et s’écrit en GraphQL ; ce routeur regroupe les vérifications qui demandent un accès au réseau côté serveur.

## Requête `user.checkEmailDomain`

Indique si un domaine peut recevoir des emails, en cherchant ses enregistrements MX. L’application l’appelle avant d’envoyer un code de connexion, pour signaler tout de suite une adresse dont le domaine n’existe pas ou n’a pas de serveur de messagerie. Cette procédure est publique, car elle sert avant toute connexion : elle reçoit donc le domaine seul, jamais l’adresse complète.

| Input | Type | Description |
| --- | --- | --- |
| `domain` | `String` | Domaine à vérifier, par exemple `example.com`. Requis. |

Elle renvoie `{ valid }`. `valid` vaut `false` quand le domaine est mal formé, inconnu, sans enregistrement MX, ou quand il déclare n’accepter aucun email. Une autre erreur DNS, comme une recherche qui dépasse deux secondes, ne met pas le domaine en cause : la réponse vaut alors `true`, pour que la connexion reste toujours possible. Le backend garde chaque réponse en mémoire pendant une heure.

```typescript
const { valid } = await trpc.user.checkEmailDomain.query({
  domain: 'example.com',
})
```

## Requête `user.checkEmailDelivery`

Indique si le code de connexion envoyé à une adresse n’a pas pu être distribué : boîte ou domaine inconnu, adresse invalide, ou adresse bloquée par le fournisseur d’emails. L’application l’interroge pendant deux minutes après l’envoi d’un code, pour signaler tout de suite une adresse qui semble erronée. Le fournisseur d’emails transmet les rejets au backend, qui les garde en mémoire pendant une heure. Cette procédure est publique, car elle sert avant toute connexion.

| Input | Type | Description |
| --- | --- | --- |
| `email` | `String` | Adresse à laquelle le code a été envoyé. Requis. |
| `since` | `Number` | Horodatage en millisecondes : seuls les rejets à partir de ce moment comptent. Requis. |

Elle renvoie `{ bounced }`.

```typescript
const { bounced } = await trpc.user.checkEmailDelivery.query({
  email: 'jane@example.com',
  since: Date.now() - 60_000,
})
```

## Query `user.getDeletionPreview`

Liste ce que la suppression du compte de l’utilisateur courant supprimerait ou détacherait : le compte, ses clés d’API et ses intégrations de calendrier, ses organisations archivées supprimées avec lui, et le contenu d’autres organisations conservé tel quel. La procédure ne prend aucun paramètre. Elle n’est pas exposée au serveur MCP.

## Mutation `user.deleteAccount`

Supprime définitivement le compte de l’utilisateur courant. La procédure ne prend aucun paramètre. L’appel est refusé avec `PRECONDITION_FAILED` tant que l’utilisateur est membre d’une organisation active : il la quitte ou la supprime d’abord. Ses organisations archivées dont il était le seul propriétaire, ou auxquelles personne d’autre n’a participé, sont supprimées avec le compte. Le compte est supprimé, ou anonymisé et désactivé tant que du contenu d’autres organisations y fait référence. Elle n’est pas exposée au serveur MCP.
